Getting agents to finish

The setup I want has two sides: one set of agents builds, and another checks the work. The builders gather material, put a version together, and iterate; the reviewers hold the output itself up against the same goal. At the end I want something I can run and inspect. Talking through the plan is only useful if it leads to finishing the job.

So at the start, I try to nail down the question, the goal, the constraints, and what counts as done. What exactly is the deliverable, which facts are fair game, and when do we stop? Those calls steer everything that follows. If the goal is still fuzzy, that’s fine; we can talk it through, as long as the conversation narrows down to something concrete to build.

Make the reviewer look at the output itself

When I hand work to a reviewing agent, I give it the source material and the finished artifact itself, not only the first agent’s write-up. If a reviewer only reads a summary, it’s bound to miss the exact same things the builder missed.

Boris Cherny’s note on giving agents verification feedback gets at the same thing: if an agent is going to keep improving a task on its own, it needs concrete signal from the current output so it knows what to fix next. Original

Long tasks also need a clean handoff so whoever takes over next can see the goal, why key choices were made, and what’s still unresolved. Anthropic’s piece on context engineering lays out practical ways to do this, like keeping structured notes. Original

Addy Osmani argues for clear stopping criteria and an independent check of the final work, which lines up closely with what I want from long-running agents. Still, even when every automated check turns green, I want to look at the output myself. Original

I also like bringing in a different model to poke holes and look for counterexamples and blind spots. The same rule applies: the second reviewer has to see the underlying evidence, not only the builder’s summary, or the same gaps slip through. When they disagree, the answer isn’t to guess; it’s to go back to the sources, the data, or what happens when you run it.
